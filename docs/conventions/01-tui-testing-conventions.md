# TUI Testing Conventions — Snow CLI 终端交互界面测试层级规范

> 定位：定义 Snow CLI 交互式终端应用（基于 React/Ink 渲染器与流式状态机）的**测试分层金字塔与质量验收规范**。
> 参照先例：`testing-scenario-tui` 终端交互规范、`skills-collection` SZ 测试架构与 `IV8` 仓 `testing-conventions.md`。
> 核心哲学：交互式 TUI 既不是传统 CLI，也不是 Web 前端。它的本质是**受限物理视口（字符网格）上的有状态流式状态机**。测试核心在于**组件纯内存渲染（~90%）与无头 PTY 终端模拟（~10%）的分层治理**。

---

## 1. 测试层级防御金字塔（The L0~L5 Testing Hierarchy）

依据测试成本、执行速度与时序稳定性比率律，Snow CLI 的终端交互测试严格划分为六层递进防御：

| 层级 | 测试技术代表 | 核心验证目标 | 成本与特征 |
|---|---|---|---|
| **L0: 数学微内核与几何不变量** | 纯代数运算、全色域扫描、圆周引力偏折 | OKLCH 互逆保真度、APCA 空间极性全色相扫描（$\ge 75\text{ Lc}$）、边界软截断单调性 | 亚毫秒级（<1ms），零环境依赖，公理级确定性 |
| **L1: 数据契约与 Schema 兼容 (CDC)** | 21-Token 契约、类型守卫、向下兼容 | 派生输出 100% 满足 ThemeColors 结构，与现有 10+ 款内置主题 100% 向下兼容 | 毫秒级（<10ms），拦截接口退化与破坏性变更 |
| **L2: 原生组件渲染与真沙盒 (Snapshot)** | `ink-testing-library` + 原生 DiffViewer / UserMessagePreview | 真实业务组件渲染一致性，绑定真实 Profile / Model，彻底剔除手绘假边框与假数据 | 毫秒级（<200ms），纯内存渲染，无 OS 进程开销 |
| **L3: TUI 状态机与输入阻尼** | 虚拟 stdin 击键序列驱动、焦点循环 | 六维字段环状焦点切换、Shift 加速步长、数值边界阻尼（Chroma 0~0.35, Bias ±0.06） | 毫秒级（<300ms），验证状态机转移与越界防护 |
| **L4: 零 I/O 抖动与资源生命周期** | `configEvents` 真实事件总线监听、堆内存差分 | 高频按键滑动阶段**严格零磁盘写入**、显式保存触发且仅触发 1 次、10k 次操作零内存泄漏 | 秒级（1~2s），高频压测防 I/O 锁死与内存膨胀 |
| **L5: 全链路 i18n 双语对称性契约** | 多语言字典对象深度比对 | `zh`、`zh-TW`、`en` 键名集合 100% 对称，零缺失键、零空翻译，防止运行时降级破损 | 毫秒级（<5ms），自动化多语言质量门禁 |

## 2. 核心规程与设计范式

### 2.1 L1 内存测试运行时基础设施（ESM Loader Hook）
由于项目在生产环境中深度魔改了 `ink` 并内联于 `source/vendor/ink`，导致外部测试工具 `ink-testing-library` 在 Node 原生 ESM 解析下无法在 `node_modules` 找到 `ink`。
- **正典规范**：通过 `scripts/test-loader.mjs` 注册自定义 ESM 解析钩子，将所有对 `ink` 的 `import` 拦截重定向至 `./source/vendor/ink/src/index.ts`；
- **配置固化**：在 `package.json` 的 `ava` 配置中注册 `--loader=./scripts/test-loader.mjs`，并开启 `TS_NODE_TRANSPILE_ONLY=true`，实现源码级热测，无需侵入打包产物。

### 2.2 确定性虚拟时序取代硬编码 Sleep（Deterministic Virtual Timers）
- **[禁止] 严禁反模式**：在虚拟 stdin 写入后使用长达数秒的无上限 sleep 或轮询等待。
- **正典规范**：利用受控微阶梯延时（如 30-50ms）等待 Ink 完成 `reconciler.batchedUpdates`，随后即刻通过 `lastFrame()` 抓取渲染帧或断言答案回调，杜绝测试时序偶发挂死。

### 2.3 自适应动态视觉锚点取代硬编码击键次数（Adaptive Visual Anchors）
- **[禁止] 严禁反模式**：在菜单漫游或页面导航中硬编码循环击键次数（如 `for _ in range(12): Down()`）。任何菜单项的新增、顺序调整或文案国际化都会使此类脚本产生错位甚至误触副作用配置（如篡改用户语言或主题配置）。
- **正典规范**：测试驱动器必须基于终端当前渲染帧中的**选中指示符**（如 `❯` 或高亮前缀）动态嗅探当前激活行；唯有当视觉锚点匹配目标语义时方可回车确认，对菜单项的物理位移与增删实现 100% 免疫。

### 2.5 视口高度不变量与零行移位契约（Viewport Height & Jitter-Free Invariant）
- **[禁止] 严禁反模式**：
  - 页面或全屏组件渲染的绝对行数（Line Count）超出标准终端安全高度（默认标准 $80 \times 24$ 物理网格）；
  - 测试用例仅断言 `frame.includes(...)` 包含某个子字符串，却从未断言当前渲染帧的总行数；
  - 交互前后（如滑动数值、模式切换）内容因为文字折行（Word Wrap）导致总行数忽高忽低发生跳变。
- **物理机制剖析**：
  - React Ink 在底层借助 `log-update` 通过 ANSI 控制码 `\u001b[<N>A` 向上回退 N 行重绘。
  - 一旦页面总行数超出终端物理行高（例如超出了 24 行），终端系统内核就会强制向上滚屏（Terminal Scrolling）。
  - 一旦发生物理滚屏，不可见的历史视口内容被推入终端回滚缓冲（Scrollback Buffer），相对光标上移无法再触及已被推上滚出的区域，导致每次重绘都会在底部多打印一行，最终在用户终端上产生疯狂行移位、重影横线累加与终端 Prompt 提示符被冲顶穿透的灾难性 Bug。
- **正典规范**：
  - **黄金行高安全预算**：全屏页面总行数严格限制在 **$\le 22$ 行**（为终端边距和 Prompt 预留至少 2 行硬缓冲）。
  - **测试视口硬门禁**：在组件测试中必须强制断言 `frame.split('\n').length <= 22`；
  - **交互抖动清零（Jitter-Free）**：在模拟连续按键重绘时，必须断言 `updatedFrame.split('\n').length === initialFrame.split('\n').length`，绝不允许行数动态跳跃；
  - **预览数据规约**：用于沙盒演示的代码和文本必须预先测算宽度，禁止在单栏/双栏中因过长产生不可控自动折行。

## 3. 红线禁令（TUI Invariants & Bans）

1. **[禁止] 为每个纯逻辑/正则算法拉起真实 PTY** — 契约与算法必须在 L0 或纯函数中完成。
2. **[禁止] 在 ESM 测试中篡改只读 module namespace exports** — 必须基于真实业务事件总线（如 `configEvents`）进行监听断言。
3. **[禁止] 业务交互组件侵入重量级外部监控或遥测副作用** — 组件应保持依赖隔离与轻量化，杜绝在测试时引入未初始化的 OpenTelemetry 抛错。
4. **[禁止] 裸正则清洗 ANSI 序列替代结构断言** — 优先使用 Ink 测试渲染器的层级断言与语义锚点。
5. **[禁止] 依赖鼠标事件驱动** — 终端应用以键盘按键（Enter/Space/Tab/Arrows/Esc/数字键）为唯一真理源。
6. **[禁止] 硬编码击键步长盲按** — 严禁死写连续按 N 次方向键等无状态假定，必须采用自适应动态视觉锚点驱动。
7. **[禁止] 渲染行数突破 22 行安全视口或交互重绘行数跳变** — 任何导致终端原生滚屏而引发 ANSI 行移位累加的代码严禁合入。

## 4. 终端组件测试验收检查单（TUI Test Acceptance Checklist）

所有新增或重构的终端交互组件，必须通过以下测试验收标准：

- [ ] **L0 算法与几何不变量**：纯代数/转换函数有极值与边界断言，耗时 $< 1\text{ms}$；
- [ ] **L1 数据契约 Schema 就绪**：Token 与结构变更 100% 向下兼容既有配置；
- [ ] **L2 原生真沙盒渲染断言**：断言标题、提示行、真实业务组件高亮，杜绝手绘假字符；
- [ ] **L2.1 视口高度不变量硬门禁**：断言首帧总行数 $\le 22$ 行，适配标准 24 行终端防滚屏；
- [ ] **L3 按键状态机与边界阻尼**：方向键导航、Tab 模式流转、极值越界截断均有测试覆盖；
- [ ] **L3.1 零行抖动防撕裂（Jitter-Free）**：连续滑动重绘时断言前后行数严格恒定不变；
- [ ] **L4 零 I/O 抖动与内存无泄露**：连续 60 次以上高频击键下磁盘写入为 0，组件卸载无悬挂监听器；
- [ ] **L5 国际化对称性就绪**：多语言字典键集合全量对齐，零未翻译字段；
- [ ] **全量执行时间门禁**：整套 TUI 组件测试套件在 3 秒内稳定完成，无偶发超时。
